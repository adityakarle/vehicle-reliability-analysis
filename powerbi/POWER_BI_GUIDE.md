# Power BI Dashboard — Step-by-Step Build Guide

This builds the dashboard referenced in the resume bullet: **10+ KPIs
(failure counts, repeat-repair rate, mileage bands, monthly trends)**.

You need **Power BI Desktop** (free, Windows only). If you're on Mac/Linux,
use a Windows VM, or Power BI Service in a browser (upload the .pbix later
from a Windows machine, or use the "Power BI Desktop" via Parallels/Bootcamp).

Files you'll import (already generated by `scripts/analysis.py`):
```
data/processed/fact_table_enriched.csv        <- main fact table
data/processed/summary_category.csv
data/processed/summary_monthly_trend.csv
data/processed/summary_monthly_by_category.csv
data/processed/summary_mileage_band.csv
data/processed/summary_model_reliability.csv
```

---

## Step 1 — Get the data in

1. Open **Power BI Desktop** → **Home → Get Data → Text/CSV**.
2. Import `fact_table_enriched.csv`. Click **Transform Data** (not Load yet).
3. In Power Query Editor, check column types:
   - `service_date` → Date
   - `repair_cost` → Decimal Number
   - `mileage_at_service`, `days_in_shop`, `is_repeat_repair` → Whole Number
   - `service_month`, `failure_category`, `mileage_band`, `make`, `model`,
     `vehicle_id`, `technician_id`, `service_center_region`, `warranty_flag` → Text
4. Repeat **Get Data → Text/CSV** for the five summary CSVs listed above.
   (You technically don't *need* the summary CSVs since Power BI/DAX can
   compute everything live from the fact table — but importing them too
   lets you show both approaches, and gives you fast-loading pre-aggregated
   tables for large-data scenarios, which is a good talking point in an
   interview.)
5. Click **Close & Apply**.

## Step 2 — Build a proper Date table (for time-intelligence)

Model view will otherwise infer weak date handling. Add a real date table:

**Home → New Table**, and enter:
```
DateTable = CALENDAR(DATE(2025,1,1), DATE(2025,12,31))
```
Then add columns (select the table → **New Column**):
```
MonthName = FORMAT('DateTable'[Date], "MMM YYYY")
MonthNumber = MONTH('DateTable'[Date])
MonthKey = FORMAT('DateTable'[Date], "YYYY-MM")
```
Go to **Model view**, drag a relationship from `DateTable[MonthKey]` to
`fact_table_enriched[service_month]` (or to a `service_month` column you
create on `DateTable`, if you match on the month-key text field). Mark
`DateTable` as a **Date Table** (right-click → Mark as date table).

## Step 3 — Build the KPI measures (DAX)

Select `fact_table_enriched` in the **Fields** pane → **New Measure** for
each of the following. This gives you 12 KPIs — comfortably clears the
"10+ KPIs" bar.

```DAX
Total Services = COUNTROWS(fact_table_enriched)

Total Repair Cost = SUM(fact_table_enriched[repair_cost])

Avg Repair Cost = AVERAGE(fact_table_enriched[repair_cost])

Avg Days In Shop = AVERAGE(fact_table_enriched[days_in_shop])

Repeat Repairs = SUM(fact_table_enriched[is_repeat_repair])

Repeat Repair Rate % =
DIVIDE([Repeat Repairs], [Total Services], 0) * 100

Unique Vehicles Serviced =
DISTINCTCOUNT(fact_table_enriched[vehicle_id])

Failures Per Vehicle =
DIVIDE([Total Services], [Unique Vehicles Serviced], 0)

Top Failure Category =
CALCULATE(
    VALUES(fact_table_enriched[failure_category]),
    TOPN(1,
        SUMMARIZE(fact_table_enriched, fact_table_enriched[failure_category],
            "cnt", COUNTROWS(fact_table_enriched)),
        [cnt], DESC
    )
)

MoM Service Change % =
VAR CurrentMonth = [Total Services]
VAR PrevMonth =
    CALCULATE(
        [Total Services],
        DATEADD('DateTable'[Date], -1, MONTH)
    )
RETURN DIVIDE(CurrentMonth - PrevMonth, PrevMonth, 0) * 100

Rolling 3-Month Avg Services =
AVERAGEX(
    DATESINPERIOD('DateTable'[Date], MAX('DateTable'[Date]), -3, MONTH),
    CALCULATE([Total Services])
)

Warranty Cost Exposure % =
DIVIDE(
    CALCULATE([Total Repair Cost], fact_table_enriched[warranty_flag] = "Y"),
    [Total Repair Cost], 0
) * 100

High-Mileage Failure Share % =
VAR HighMileageCount =
    CALCULATE(
        [Total Services],
        fact_table_enriched[mileage_band] IN {"100k-150k", "150k+"}
    )
RETURN DIVIDE(HighMileageCount, [Total Services], 0) * 100
```

That's 13 measures — pick whichever 10+ tell the clearest story for your
dashboard; you don't need every single one on the canvas.

## Step 4 — Build the report pages

**Page 1 — Executive Overview**
- 4–5 **Card** visuals across the top: `Total Services`, `Repeat Repair
  Rate %`, `Avg Repair Cost`, `Unique Vehicles Serviced`, `Warranty Cost
  Exposure %`.
- **Clustered bar chart**: Axis = `failure_category`, Value = `Total
  Services` (or `Failure Count` from summary_category.csv). Sort
  descending.
- **Line chart**: Axis = `DateTable[MonthName]` (sorted by MonthNumber —
  right-click the column → **Sort by column** → MonthNumber), Values =
  `Total Services` and `Rolling 3-Month Avg Services`.
- **Donut chart**: `mileage_band` by `Total Services`.

**Page 2 — Failure & Repeat-Repair Deep Dive**
- **Matrix visual**: Rows = `failure_category`, Columns = `mileage_band`,
  Values = `Total Services`. This directly visualizes the
  mileage-vs-failure relationship.
- **Stacked column chart**: Axis = `MonthName`, Legend = `failure_category`,
  Values = `Total Services` — shows how failure mix shifts month to month.
- **Bar chart**: Axis = `failure_category`, Values = `Repeat Repair Rate %`
  — shows which categories are most prone to comebacks.
- **Table**: `make`, `model`, `Failures Per Vehicle` from
  summary_model_reliability.csv, sorted descending — the "least reliable
  models" leaderboard.

**Page 3 — Cost & Warranty**
- Card: `Total Repair Cost`, `Avg Repair Cost`, `Warranty Cost Exposure %`.
- Bar chart: `failure_category` by `Avg Repair Cost`.
- Bar chart: `service_center_region` by `Total Repair Cost`.

## Step 5 — Slicers (interactivity)

Add slicers for `failure_category`, `mileage_band`, `make`, and a date
range slicer bound to `DateTable[Date]`. Put them on the left side of each
page (or use a **Sync Slicers** setup across pages: **View → Sync
Slicers**).

## Step 6 — Formatting pass

- Format → Theme: pick a clean built-in theme, or apply a custom theme JSON.
- Set consistent number formatting: currency for costs (`$#,##0`),
  percentage for rates (`0.0%` — note: if a measure already multiplies by
  100, format as a plain number with `0.0"%"` instead of true percentage
  formatting, to avoid double-multiplying).
- Add a title text box per page and a footer note: "Synthetic dataset —
  personal portfolio project."

## Step 7 — Save and export

1. **File → Save As** → `powerbi/vehicle_reliability_dashboard.pbix`.
2. Optional: **File → Export → Export to PDF** for a static copy to attach
   to your resume/portfolio site (screenshots work too — Win+Shift+S).
3. If you want it shareable as a live link: **Publish** to Power BI Service
   (needs a free Power BI account) → **File → Publish → Publish to Power
   BI**. Then in the Service, you can **File → Embed report → Publish to
   web** (only do this since the dataset is synthetic — never publish real
   customer/vehicle data this way) or share via org link.

## Step 8 — Add it back into the GitHub repo

Power BI files are binary, but GitHub handles them fine as a normal binary
blob (no special LFS needed at this size):

```bash
cp path\to\vehicle_reliability_dashboard.pbix powerbi/
git add powerbi/vehicle_reliability_dashboard.pbix
git commit -m "Add Power BI dashboard (.pbix)"
git push
```

Also drop 2–3 dashboard screenshots into `powerbi/screenshots/` and
reference them in the main `README.md` — recruiters looking at a GitHub
repo almost never open a `.pbix` file, but they will look at an embedded
screenshot.
